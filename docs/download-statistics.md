# Download statistics

AutoSwarm records acquisition metrics for `HKUDS/AutoSwarm` from **2026-10-24 (UTC)**. Collection runs in the repository, independently of the installed agent runtime. It requires no database or server.

| Metric | Source and interpretation |
| --- | --- |
| Repository clones | GitHub's daily full-clone records, merged by UTC date. Each collection refreshes the available 14-day window and retains older recorded days. Daily unique cloners are stored individually, never summed into lifetime users. |
| Release asset downloads | Uploaded asset counters, retained by asset ID. Assets created on/after the start date include their full count; older assets use their first observed counter as a baseline. Removed assets retain their last observed count; a re-upload with a new ID is separate. |

These counters do not measure installations or users and are not added together as a single total. They do not cover fetch/pull, raw files, GitHub's automatically generated source archives, or PyPI. GitHub source data can arrive late. Missing dates are not invented as zero; `pending` indicates no data since the start date, and `+`/orange indicates recorded counts with gaps. The latest source date and missing dates are shown on the statistics branch. Gaps outside GitHub's available traffic window cannot be reconstructed.

## Enable daily collection

1. Create a dedicated fine-grained GitHub token for **HKUDS/AutoSwarm only**, with repository **Administration: read** and **Contents: read**. An organization may require approval. Store it as the repository Actions secret **`TRAFFIC_TOKEN`**. Do not put credentials in code, data files, or chat. The ordinary workflow `GITHUB_TOKEN` publishes the statistics branch; it is not the traffic-reading credential.
2. Publish `.github/workflows/download-statistics.yml` on the default branch. The job is restricted to the canonical `HKUDS/AutoSwarm` repository so development forks do not inflate the public counters.
3. Run **Actions → Download statistics → Run workflow** once. Confirm it creates/updates [`download-stats`](https://github.com/HKUDS/AutoSwarm/tree/download-stats).

The workflow then runs daily at **03:17 UTC**, and can also run manually. Overlapping manual/scheduled runs are serialized. It loads existing history from `download-stats`, or uses `download-statistics-baseline.json` for the first run. It publishes only `history.json`, the statistics README, and two badge JSON files on that branch. Main code and runtime configuration are not modified by collection. A failed API request or invalid state fails the job before publication; existing remote history remains intact. A rerun can recover days still returned by GitHub. Watch failed runs and refresh the secret when its credential changes/expires.

GitHub schedules may be delayed and are automatically disabled after prolonged inactivity in public repositories. Check that the workflow remains enabled; daily collection is not a guarantee against a gap longer than GitHub's source retention window.

## Manual collection

With `TRAFFIC_TOKEN` available securely in the process environment:

```bash
python scripts/collect_downloads.py --repository HKUDS/AutoSwarm --since 2026-10-24 --output /path/to/statistics
```

Keep the same output directory's `history.json` for subsequent runs. For the original baseline, copy `docs/download-statistics-baseline.json` there as `history.json` before the first collection. Repository and start date must match existing history. This command writes local files only; the workflow publishes them.

## README badges

After the first successful publication, use Shields' endpoint badges backed by the public `clones-badge.json` and `release-downloads-badge.json` on `download-stats`, linking to its README. Keep the labels **clones since 2026-10-24** and **Release downloads since 2026-10-24** so the metrics are not confused with users or an all-channel download total. Badges are generated by the collector rather than incremented on page views.

Sources: [GitHub traffic API](https://docs.github.com/en/rest/metrics/traffic#get-repository-clones), [Release assets API](https://docs.github.com/en/rest/releases/assets#list-release-assets), [scheduled workflow behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
